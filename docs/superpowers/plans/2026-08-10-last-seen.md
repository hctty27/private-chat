# Last Seen Presence Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Persist each user's latest confirmed WebSocket activity and show it only in desktop/mobile active-chat headers when the contact is offline.

**Architecture:** Keep Redis `online:<userId>` as the real-time online-state source. Add PostgreSQL `t_user.last_seen_at TIMESTAMPTZ` for durable history, and isolate persistence/throttling in a focused presence service so heartbeat writes are limited to once per user per 60 seconds. Contact API/WebSocket payloads carry an RFC3339 UTC `lastSeenAt`; the frontend formats it in browser-local time only in chat headers.

**Tech Stack:** Go 1.23, Gin, Gorilla WebSocket, GORM, PostgreSQL 16, go-redis v9, Vue 3, Pinia, TypeScript 5.8, GitHub Actions.

## Global Constraints

- Redis remains authoritative for current `online` state.
- `lastSeenAt` means the latest server-confirmed active authenticated WebSocket-session time; ordinary HTTP/file activity must not update it.
- PostgreSQL storage uses nullable `TIMESTAMPTZ`.
- API/WebSocket `lastSeenAt` values use RFC3339 UTC (`...Z`) so browser parsing is unambiguous.
- Successful WebSocket registration persists immediately.
- Heartbeat persistence is throttled to at most approximately one PostgreSQL update per user per 60 seconds.
- Current-session disconnect persists immediately and broadcasts the same captured timestamp.
- A stale/replaced session must not mark the user offline or overwrite last seen on disconnect.
- Redis throttle or PostgreSQL persistence failures are logged but must not terminate an otherwise healthy WebSocket session.
- `ContactList.vue` stays visually unchanged and never renders last-seen text.
- Desktop `ChatPage.vue` and mobile `MobileChat.vue` are the only UI surfaces that render last-seen text.
- No new HTTP endpoint, privacy setting, per-device presence model, or relative "x minutes ago" timer.

- [ ] **Step 3: Implement repository and throttle adapters**

```go
const lastSeenPersistInterval = time.Minute

func lastSeenThrottleKey(userID int64) string {
    return fmt.Sprintf("presence:last_seen:persist:%d", userID)
}

type lastSeenRepository interface {
    UpdateLastSeen(context.Context, int64, time.Time) error
}

type gormLastSeenRepository struct {
    db *gorm.DB
}

func (r gormLastSeenRepository) UpdateLastSeen(ctx context.Context, userID int64, at time.Time) error {
    return r.db.WithContext(ctx).
        Model(&model.User{}).
        Where("id = ?", userID).
        Update("last_seen_at", at.UTC()).Error
}

type lastSeenThrottle interface {
    Acquire(context.Context, int64, time.Duration) (bool, error)
}

type redisLastSeenThrottle struct {
    client *redis.Client
}

func (r redisLastSeenThrottle) Acquire(ctx context.Context, userID int64, window time.Duration) (bool, error) {
    return r.client.SetNX(ctx, lastSeenThrottleKey(userID), "1", window).Result()
}
```

`SetNX(..., expiration)` maps to Redis `SET ... NX` with expiry in go-redis; do not implement separate `SETNX` then `EXPIRE` calls.

- [ ] **Step 4: Implement the service**

Add:

```go
type presenceService struct {
    repo     lastSeenRepository
    throttle lastSeenThrottle
}

func newPresenceService(repo lastSeenRepository, throttle lastSeenThrottle) *presenceService {
    return &presenceService{repo: repo, throttle: throttle}
}

func (p *presenceService) PersistImmediate(ctx context.Context, userID int64, at time.Time) error {
    return p.repo.UpdateLastSeen(ctx, userID, at.UTC())
}

func (p *presenceService) PersistThrottled(ctx context.Context, userID int64, at time.Time) error {
    allowed, err := p.throttle.Acquire(ctx, userID, lastSeenPersistInterval)
    if err != nil {
        return err
    }
    if !allowed {
        return nil
    }
    return p.repo.UpdateLastSeen(ctx, userID, at.UTC())
}

func formatPresenceTime(t time.Time) string {
    return t.UTC().Format(time.RFC3339)
}
```

Add to `frontend/src/utils/time.ts`:

```ts
export function formatLastSeen(dateStr: string | null, now = new Date()): string {
  if (!dateStr) return '离线'
  const date = new Date(dateStr)
  if (Number.isNaN(date.getTime())) return '离线'

  const h = String(date.getHours()).padStart(2, '0')
  const m = String(date.getMinutes()).padStart(2, '0')
  const timeStr = `${h}:${m}`

  const todayStart = new Date(now.getFullYear(), now.getMonth(), now.getDate())
  const dateStart = new Date(date.getFullYear(), date.getMonth(), date.getDate())
  const diffDays = Math.round((todayStart.getTime() - dateStart.getTime()) / 86400000)

  if (diffDays === 0) return `最后上线 今天 ${timeStr}`
  if (diffDays === 1) return `最后上线 昨天 ${timeStr}`

  const month = String(date.getMonth() + 1).padStart(2, '0')
  const day = String(date.getDate()).padStart(2, '0')
  if (date.getFullYear() === now.getFullYear()) {
    return `最后上线 ${month}-${day} ${timeStr}`
  }
  return `最后上线 ${date.getFullYear()}-${month}-${day} ${timeStr}`
}
```

The day calculation follows the current project's existing `formatChatTime` local-calendar convention.
